# Lab 8, M3: семантичний і гібридний пошук

```
uv run findex index data/gutenberg -o index_arr.bin --kind array --positions
uv run findex embed index_arr.bin                     # -> index_arr.emb.npz
uv run findex search index_arr.bin "conspirators stab the roman ruler" --mode semantic
uv run findex search index_arr.bin "emma harriet" --mode hybrid
GET /search?q=...&mode=keyword|semantic|hybrid        (і перемикач "Слова / За змістом / Гібрид" на сторінці)
```

## Як це влаштовано (`src/findex/semantic.py`)

- **Модель:** `sentence-transformers/all-MiniLM-L6-v2` (384 виміри) через **fastembed** (ONNX Runtime). Без PyTorch: модель додає ~190 MB RAM замість ~1 GB, а один запит рахується за ~3 мс на CPU.
- **Фрагменти:** документ (абзац) ділиться на шматки до 200 слів. Більшість абзаців — це один шматок, бо медіана 48 слів. Разом 49 240 фрагментів.
- **`findex embed`:** вектори нормуються до довжини 1, тож косинус = скалярний добуток. Тексти сортуються за довжиною перед пакетами: у пакеті всі тексти доповнюються до найдовшого, тож це в 3.3 рази швидше (з 39 до 129 документів/с на i7-11700K). Повний корпус займає близько 6 хвилин.
- **Файл `.emb.npz`:** вектори в `int8` з масштабом на рядок: **19.3 MB** замість 73 MB у `float32`. Похибка косинуса менша за 0.02 (тест), і рейтинг майже не змінюється.
- **semantic:** `sims = E @ q` — одне множення матриці 49 240 × 384 на вектор запиту. `np.maximum.reduceat` дає найкращий фрагмент кожного документа, а `np.argpartition` — топ-k.
- **hybrid:** топ-100 BM25 і топ-100 семантики зливаються через **Reciprocal Rank Fusion**: `score(d) = Σ 1/(60 + rank)`. RRF бере лише місця, а не бали: BM25 (0..30) і косинус (0..1) мають різні шкали, і нормалізувати їх не треба. Якщо запит не розбирається як булевий, лишається тільки семантичний рейтинг.

## Пам'ять (для Render, 512 MB)

Щоб модель влізла, індекс тепер може зберігатися компактно: `--kind array --positions`. Постинги й позиції лежать в `array('I')`, а об'єкти `Posting` створюються лише на час фразового запиту. Ранжування NumPy читає ці масиви через `np.frombuffer` без копії.

| | `slots` + позиції (Lab 7) | `array` + позиції (Lab 8) |
|---|---:|---:|
| файл | 28.3 MB | 28.6 MB |
| `load()` | 1.9 s | **0.20 s** |
| RSS індексу | 268 MB | **97 MB** |
| + масиви NumPy для скорера | +13 MB | 0 (`np.frombuffer` прямо з `array('I')` на кожен запит) |

**Docker-контейнер з `-m 512m`** (ліміт як на Render Free; індекс `array` з позиціями + ембединги + модель):

| | RSS | пік (VmHWM) |
|---|---:|---:|
| перша версія (копії при завантаженні ембедингів, копія постингів) | 465 MB | **529 MB** — більше за ліміт |

**Що з цього видно.**

- **Перефрази: ключовий пошук не знаходить нічого (0.00).** Запит з 8–10 слів через неявне AND вимагає всіх слів у одному абзаці, а слів «conspirators», «roman ruler» в абзацах про вбивство Цезаря немає. Семантика на тому ж запиті дає 0.8 («They stab Caesar.», промова Антонія про змовників): модель знає, що Цезар — римський правитель, а змова — це змовники.
- **Семантика не всесильна.** «Принц говорить з духом убитого батька» не знайшов жодної сцени Гамлета з Привидом. Тексти Шекспіра тут в оригінальному правописі 1603 року («Ghost. I finde thee apt…»), і маленька модель, навчена на сучасній англійській, погано їх розуміє. «Морське чудовисько й одержимий моряк» дав загальні абзаци Мелвілла про море, а не про Мобі Діка: ця тема розлита по всій книзі, а модель бачить лише один абзац.
- **На звичайних запитах з іменами семантика гірша за BM25 (0.42 проти 0.50).** На `lady macbeth` вона віддає перевагу коротким «Enter Macbeth.»: вектор імені близький до запиту, а BM25 вимагає обох слів. Зате на `emma harriet` і `brutus OR cassius` семантика краща (0.8/0.6 проти 0.2): BM25 тут ставить нагору однорядкові репліки (проблема `b=0.75` з Lab 3), а семантика бере змістовні абзаци про стосунки героїв.
- **Гібрид — найкращий загалом (0.51 на всіх 15, 0.62 на запитах Lab 3).** RRF піднімає документи, які високо в обох рейтингах. Там, де один з методів помиляється, а другий ні, гібрид бере правильні (`alice`, `hamlet`, `lady macbeth` — 1.0, як у BM25). На перефразах він дорівнює семантиці, бо булевий рейтинг порожній.
- **`captain ahab`, `father brown`, `white whale` — 0 майже скрізь.** Мій критерій вимагає «абзац про героя», а обидва рейтинги люблять короткі репліки з іменем. Це питання не стільки моделі, скільки поділу на документи (Lab 2: абзац = документ).
