# Сценарій демо-відео (2–3 хв)

Запис екрана й голос, обличчя не потрібне. Записувати можна в Xbox Game Bar (`Win + Alt + R`) або OBS. Викласти на YouTube з доступом «За посиланням» і вставити посилання в README, розділ «Відео».

**Перед записом:** відкрити https://findex-0rmn.onrender.com заздалегідь, щоб сервер прокинувся (на безкоштовному плані він засинає). Окремі вкладки: README на GitHub і `docs/profiling.md`. Термінал з папкою проєкту.

---

**0:00–0:20 — що це.** _(README на GitHub, перший екран)_
«Це findex — пошукова система, яку я написав з нуля на Python за вісім лабораторних. Корпус — 18 книг Project Gutenberg, майже 48 тисяч абзаців. Вона працює онлайн, ось адреса».

**0:20–0:55 — пошук за словами.** _(сайт)_
Ввести `"white whale" ahab`, режим «Слова».
«Це булевий запит: фраза в лапках плюс слово. Індекс зберігає позиції слів, тому фраза шукається точно. Результати ранжує BM25 — та сама формула, що в Elasticsearch. Слова з запиту підсвічені». Відкрити один результат, показати сторінку документа, повернутися.

**0:55–1:30 — пошук за змістом.** _(сайт)_
Ввести `conspirators stab the roman ruler`. Спершу режим «Слова»: «нічого не знайдено — таких слів поруч у тексті немає». Потім «За змістом»: «а тут перший результат — "They stab Caesar." Кожен абзац перетворений на вектор моделлю all-MiniLM-L6-v2, і пошук — це одне множення матриці на вектор запиту». Перемкнути на «Гібрид»: «гібрид зливає обидва рейтинги через Reciprocal Rank Fusion — на моїх 15 розмічених запитах він найкращий».

**1:30–2:05 — вимір, яким пишаюсь.** _(README, таблиця Lab 8, NumPy)_
«Профайлер показав, що пошук — це Python-цикл по десятках тисяч об'єктів. Я переписав BM25 на масиви NumPy, і на частому слові стало в 15.6 раза швидше. Рейтинг при цьому однаковий до останнього біта — це перевіряє тест. А на слові, що трапляється один раз, NumPy навіть повільніший: накладні витрати більші за саму роботу».

**2:05–2:40 — баг, який мене чогось навчив.** _(README, таблиця пам'яті)_
«Коли я засунув сервіс у Docker, він їв 546 мегабайтів, а безкоштовний Render дає 512. Виявилось, що pickle під час завантаження тримає копію кожного з мільйона об'єктів у своїй таблиці. Я змінив формат на компактні масиви — і тепер навіть разом з нейромережею для семантичного пошуку сервіс займає 414 мегабайтів».

**2:40–2:55 — завершення.** _(README, розділ «Обмеження»)_
«Обмеження я чесно виписав у README: корпус маленький, модель англійська, а безкоштовний сервер повільний. Код, тести й усі виміри — на GitHub. Дякую».
